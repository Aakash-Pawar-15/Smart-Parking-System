**Parkwise – IoT-Based Smart Parking System**

Parkwise is an IoT-based smart parking prototype built using an ESP32 and four IR sensors. It monitors parking-slot occupancy and displays live availability through a web dashboard hosted directly by the ESP32.

The dashboard shows the status of each slot, the total number of occupied and available spaces, and a mobile-camera stream area for parking surveillance.
Features
- Live slot monitoring: Tracks four parking slots: A1, A2, B1, and B2.
- Automatic availability count: Displays occupied and available slot totals.
- Wi-Fi access point: The ESP32 creates its own Wi-Fi network, so a separate router or internet connection is not required for the dashboard.
- Web dashboard: Shows live parking information in a responsive interface for desktop and mobile screens.
- Camera stream area: Displays a camera stream from a mobile phone when the phone's streaming address is reachable.
- Sensor debounce: Uses a 150 ms stability check to reduce false changes caused by fluctuating sensor readings.
Hardware Requirements
- ESP32 development board
- 4 IR obstacle/vehicle-detection sensors
- Jumper wires
- Breadboard or suitable mounting/prototyping board
- USB cable and power source for the ESP32
- Smartphone and a compatible camera-streaming app (optional, for the camera section)
Pin Connections
Connect the four sensor digital outputs to the ESP32 as follows:
Parking slot	IR sensor OUT	ESP32 GPIO
A1	OUT	GPIO 18
A2	OUT	GPIO 19
B1	OUT	GPIO 23
B2	OUT	GPIO 25


Also connect each sensor's VCC and GND to a suitable power supply and common ground, following the sensor module's voltage requirements. Check the ESP32 and sensor module specifications before wiring; do not apply 5 V to an ESP32 GPIO.
Software Requirements
- Arduino IDE
- ESP32 board support package installed in Arduino IDE
- ESP32-compatible USB driver, if required by your board
The sketch uses these libraries:
- WiFi.h – ESP32 Wi-Fi access point functionality
- WebServer.h – HTTP web server
These are included with the ESP32 Arduino core.
Setup and Installation
1. Install the Arduino IDE.
2. Install ESP32 board support in the Arduino IDE.
3. Connect the ESP32 to your computer using USB.
4. Open the project .ino file in Arduino IDE.
5. Select the correct ESP32 board and COM port.
6. Check the sensor wiring against the pin table above.
7. Upload the sketch to the ESP32.
8. Open Serial Monitor and set the baud rate to 115200.
9. After startup, connect a phone or computer to the ESP32 Wi-Fi network:
   - Wi-Fi name (SSID): SmartParking
   - Password: parking123
10. Open the dashboard address printed in Serial Monitor. With the default ESP32 access-point configuration, it is normally:
    http://192.168.4.1
11. Place an object or vehicle in front of each sensor to test whether the corresponding slot changes between AVAILABLE and OCCUPIED.
Important: The Wi-Fi credentials shown above are the defaults in the sketch. Change them before using the project outside a controlled demonstration.

How It Works
1. When powered on, the ESP32 configures the four sensor pins as inputs.
2. It reads the initial sensor states so the dashboard starts with the detected slot conditions.
3. The ESP32 creates a Wi-Fi access point named SmartParking.
4. A web server starts on port 80 and serves the dashboard at /.
5. The browser requests /status every two seconds.
6. The ESP32 reads the sensor states and returns JSON data containing each slot's status and the occupied/available totals.
7. The dashboard updates the slot cards and totals without reloading the page.
8. A sensor state is accepted only after it remains stable for the configured debounce period.
Sensor Logic
The sketch currently uses:
const bool ACTIVE_LOW = true;
With this setting, a sensor reading of LOW means an object is detected and the slot is marked OCCUPIED. If your sensor module gives HIGH when an object is detected, change ACTIVE_LOW to false and test the behavior.

The debounce interval is:
const unsigned long DEBOUNCE_MS = 150;
You can adjust this value if your sensors produce unstable readings.
Camera Stream Configuration (Optional)
The dashboard's camera image element currently uses this stream address:
http://192.168.4.2:8080/video
This is a separate mobile-camera stream; it is not generated by the four IR sensors or by the ESP32 web server. To use it:
1. Connect the phone running the camera-streaming app to the same network as the device viewing the dashboard, or configure the network so the stream is reachable.
2. Configure the camera app to provide an MJPEG-compatible stream at the expected address and port.
3. Update the src value of the dashboard's cameraFeed image element to match the actual stream URL.
4. Open the dashboard and check the camera status message.
If the stream does not load, the parking-slot monitoring can still work independently.
API Endpoint
The ESP32 provides one JSON endpoint:
Endpoint	Method	Purpose
/	GET	Serves the Parkwise dashboard
/status	GET	Returns current slot states and availability totals


Example /status response:
{
  "A1": false,
  "A2": true,
  "B1": false,
  "B2": true,
  "occupied": 2,
  "available": 2
}
In this example, true means occupied and false means available.

Troubleshooting
Problem	What to check
ESP32 Wi-Fi network is not visible	Check USB power, board selection, Serial Monitor messages, and whether the access point started successfully.
Dashboard does not open	Connect to SmartParking and use the IP address printed in Serial Monitor.
A slot always shows OCCUPIED or AVAILABLE	Check sensor power, common GND, OUT pin wiring, sensor adjustment, and the ACTIVE_LOW setting.
Slot status changes unexpectedly	Check sensor alignment and adjust DEBOUNCE_MS if needed.
Camera feed is unavailable	Verify the phone stream is running, the URL/port are correct, and the stream is reachable from the dashboard device.


Limitations and Notes
- This version monitors four parking slots.
- The dashboard is hosted on the ESP32's local Wi-Fi access point; internet access is not provided by this setup.
- The camera stream is optional and depends on an external mobile-camera streaming app.
- The current sketch does not include cloud storage, user accounts, payment processing, or historical parking records.
- This is a prototype. For real-world deployment, add appropriate electrical protection, secure the network, use a suitable enclosure, and test sensor performance in the intended environment.
